●
409 PROD IDs completely absent from UAT
IT-type intra-day trades, Crude/WTI instruments, THE/TTF/WTI market areas, and SIDE 2/3 transactions are 100% missing — entire product categories not yet supported in UAT.
409 IDs / 35%
●
SIDE encoding completely different across all 752 shared IDs
Prod always sends SIDE=0; UAT sends 1 or 2. Different coding scheme, needs normalization before comparison.
752 / 752
●
TRAN_INS_TYPE mapping mismatch (ST/SP → SP_ST)
UAT collapses straight trades (ST) and spreads (SP) into a single SP_ST type. BL_ST and BL_SP_ST also mapped to SP_ST.
752 / 752
●
UNIT label convention differs (MW → MWh, t → mt)
Units encode the same values but use different labels. Prod: MW, t, th — UAT: MWh, mt, therm.
745 / 752
●
INS_CLASS B missing from UAT
Prod distinguishes B (Block) and F (Financial). UAT maps all to F — 498 IDs affected.
498 / 752
●
MARKET_AREA naming differs (API2 → ARA, THE → German Grid)
Same geographical markets, different naming convention. Affects 111 IDs.
111 / 752
●
Volume inflation in UAT (3x–6x row multiplication)
498 IDs have volume mismatches; ~350 are pure row multiplication — UAT generates 3–6x more rows at the same per-row volume.
498 / 752
●
PRICE = 0 in PROD for 19 IDs where UAT has real prices
Prod is not populating the PRICE field for these transactions. This is a Prod data gap, not a UAT bug.
19 IDs
●
UAT generates extra V (Void) status records
64 IDs where Prod has [C] but UAT has [C|V], or Prod has [E] but UAT has [E|V]. UAT sends explicit void before cancellation.
64 / 752
●
ORDER_TYPE naming (LIM/MAR → ICE) for 84 IDs
Prod uses LIM/MAR abbreviations; UAT uses ICE for the same order types.
84 / 752
